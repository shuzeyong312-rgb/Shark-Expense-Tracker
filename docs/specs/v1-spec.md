# 1. 产品定义

## 1.1 产品定位

一款先面向个人使用、未来可能开放的轻量级 Android 记账 APP。V1 不为尚未确定的多用户商业化场景提前引入账号、服务端或复杂架构。

核心目标：

1.  快速记录收入和支出；
2.  按月份查看账单明细；
3.  通过周、月、年统计了解收支变化；
4.  通过一级分类和二级备注标签分析消费；
5.  用户能够自行导出和备份数据；
6.  不使用开屏广告、信息流广告、会员付费墙或功能付费解锁。

## 1.2 目标平台

- 仅开发 Android 手机 APP。
- 不开发 iOS 版本。
- 不开发独立 PC 客户端或 Web 管理后台。
- 手机是唯一日常记账和数据管理入口。
- 电脑辅助场景通过导出的 CSV、JSON 文件实现查看、归档和备份。
- V1 不提供手机与电脑实时同步。

产品名称暂未冻结。鲨鱼记账仅作为参考产品称呼，正式 APP 不直接使用其商标、Logo 或未获授权的专有素材；图标应使用自绘或有明确使用许可的资源。

## 1.3 产品原则

- 本地优先：核心功能离线可用。
- 数据归用户：账单保存在本机，用户可以完整导出。
- 低维护：不引入后端、账号体系、云数据库和复杂基础设施。
- 无商业干扰：无广告、无会员、无功能锁。
- 交互优先：记账路径短，常用备注可快捷选择。
- 统计可信：所有统计从账单数据计算，不维护容易失真的冗余汇总值。

## 1.4 币种约定

V1 沿用原型中的 `¥` 显示，暂按人民币 CNY 处理：

- 单一币种；
- 不支持多币种；
- 不提供汇率转换；
- 金额精确到分。

原型只明确了 `¥` 符号，尚未明确币种编码；本 Spec 暂按 CNY 实现，冻结前需确认。

# 3. 页面与导航规格

## 3.1 底部导航

固定五等分布局，顺序不得改变：

1.  明细
2.  图表
3.  中间悬浮记账按钮
4.  账伴
5.  我的

规则：

- 记账按钮占据第三个等分区域，视觉上悬浮于导航栏上方。
- 第四个位置是账伴入口，不是空白占位。
- 点击记账按钮打开独立记账页面。
- 明细、图表、账伴、我的为一级导航。
- 记账页、分类详情页、备注详情页属于二级页面，进入后隐藏底部导航。
- Android 系统返回键遵循页面返回栈；弹窗打开时优先关闭弹窗。

## 3.2 明细首页

### 顶部区域与固定行为

首次启动默认定位到设备当前年月；用户主动选择历史月份或通过上拉加载切换月份后，返回明细页仍保留当前选中的年月。顶部固定显示：

- 当前年份和月份及月份下拉入口；
- 当前选中月份收入总额；
- 当前选中月份支出总额。

顶部黄色区域固定。用户上下滚动账单时，顶部黄色区域保持原位，只有账单列表内容区域独立滚动。黄色区域下方不再设置快捷操作区或空白占位，账单列表直接开始。

### 月份选择器

点击左上角月份入口后，从屏幕底部滑出选择面板：

- 年份滚轮；
- 月份滚轮；
- 当前选中项高亮；
- 取消、确定按钮；
- 点击遮罩关闭时等同取消；
- 点击取消不修改当前月份；
- 点击确定才应用新月份，并将账单列表滚动位置重置到顶部。

选择年份/月时必须正确处理跨年，例如 2026 年 12 月切换到 2027 年 1 月。

### 账单列表与滚动结构

- 账单列表只展示当前选中自然月的全部账单，不提供“全部 / 支出 / 收入”筛选。
- 列表上方不再重复显示年月；月份以顶部左侧月份选择器为唯一入口和显示依据。
- 只有顶部黄色区域固定；账单列表直接从黄色区域下方开始并独立滚动。
- 按账单日期倒序分组。
- 同一天内按创建时间倒序。
- 每个日期组显示当天支出总额和收入总额。
- 账单行显示分类图标、备注或分类名称、金额。
- 有备注时：备注作为主标题，一级分类作为副标题。
- 无备注时：一级分类作为主标题。
- 支出金额使用负号展示；收入金额使用正号展示。
- 点击账单行进入编辑页面。
- 长按账单行可打开账单操作面板。
- 空月份显示明确空状态，同时仍允许继续上拉加载更早月份。

### 上拉加载上月账单

用户滚动到当前月份账单列表底部后，继续向上滑动时触发上拉加载交互：

1. 到达列表底部后，列表底部出现轻量提示“上拉查看上月数据”。
2. 用户继续向上拉动，达到触发距离后，提示切换为“松开查看上月数据”。
3. 用户松开手指后，切换到当前选中月份的上一个自然月。
4. 切换后自动将列表滚动位置重置到新月份顶部。
5. 顶部年份、月份、收入总额、支出总额和账单列表必须同步更新；所有统计均根据新月份账单重新计算。
6. 如果上一个月没有账单，仍然切换月份，显示空月份状态及 0.00 收支汇总；用户可以继续上拉进入更早月份。
7. 未达到触发距离就松手，不切换月份，提示恢复为“上拉查看上月数据”。
8. 月份跨年时必须正确处理，例如从 2026 年 1 月上拉后进入 2025 年 12 月。
9. 通过左上角月份选择器手动切换月份时，使用同一套月份和统计刷新逻辑，并重置列表滚动位置。
10. 上拉加载只改变当前查看月份，不创建、修改或删除任何账单。

原型中以约 72dp 作为触发距离的演示值；Android 正式实现可以根据系统手势体验微调，但必须保留“提示出现 → 达到阈值后提示松开 → 松手切换月份”的完整交互顺序。桌面浏览器原型可用滚轮继续滚动到列表底部后累积触发距离，并点击已变为“松开查看上月数据”的提示完成演示。


## 3.3 记账流程与分类选择

### 入口与第一阶段：一级分类选择

点击底部中间的记账按钮后，先进入独立的一级分类选择页面，**不得直接显示金额输入框、备注输入框或数字键盘**。

页面规则：

- 默认进入“支出”分类；顶部提供“支出 / 收入”切换和右侧“取消”。
- 默认展示当前收支类型下已启用的一级分类，四列网格排列。
- 分类图标使用浅灰圆形底、深灰线性图标和分类名称；不显示金额、备注或键盘。
- 网格最后一个位置始终保留“设置”入口；它不是分类数据，不参与排序、隐藏或删除。
- “设置”入口必须常驻，即使用户隐藏了全部其他分类也不能消失。
- 点击某个一级分类后，才从屏幕底部滑出第二阶段的记账操作面板。
- 点击“取消”返回明细页，不产生账单。
- 切换支出/收入时只刷新对应类型的已启用分类，不自动打开记账操作面板。

### 第二阶段：底部记账操作面板

点击一级分类后，页面背景保持一级分类选择页，背景加遮罩，记账操作面板从底部滑入。

面板包含：

- 当前一级分类图标和名称；点击分类信息可收起面板，返回分类选择页更换分类；
- 金额显示；
- 备注输入框；
- 日期选择；
- 当前一级分类对应的快捷二级备注；
- 自定义数字键盘；
- 完成/保存操作。

交互规则：

- 新增账单时，必须先选择一级分类，随后才允许输入金额和备注。
- 金额输入规则沿用本 Spec 后续约定：最多两位小数、金额必须大于 0、金额以整数分存储。
- 快捷二级备注与当前一级分类关联；切换一级分类后必须显示新分类对应的快捷备注。
- 收起面板返回分类选择页时，已输入的金额、备注和日期暂时保留，重新选择分类后继续编辑。
- 取消新增账单不保存数据；完成保存后关闭面板并返回明细页。
- 编辑已有账单时直接打开底部操作面板，预填原账单信息，不要求用户再次经过分类选择步骤；用户仍可通过面板顶部分类入口更换分类。
- 删除账单仍须经过明确确认。

### 收支类型

- 支出、收入两个选项。
- 新增账单默认进入支出分类选择页。
- 默认支出分类为当前已启用列表中的第一项；默认收入分类为当前已启用收入列表中的第一项。
- 切换为另一收支类型时，分类选择页切换到该类型已启用的分类。
- 分类类型必须与账单收支类型一致。

### 金额输入

- 使用底部操作面板中的自定义数字键盘。
- 支持数字、小数点、退格。
- 最多保留两位小数。
- 金额必须大于 0。
- 金额以整数分存储，禁止使用浮点数作为数据库金额字段。
- 不允许保存空金额、0 金额或负金额。
- 保存前进行金额合法性校验。

### 日期

- 默认使用设备当前日期；原型中可沿用演示日期。
- 支持选择历史日期。
- 保存后按账单日期归入对应月份。

### 备注与二级标签

- 备注为空时不创建二级标签。
- 输入备注后，保存时自动创建或复用当前一级分类下的二级标签。
- 同一分类下相同规范化备注只保留一个标签。
- 不同一级分类允许有相同备注文本，但统计相互独立。
- 记账面板中的快捷备注只显示当前一级分类的标签。
- 快捷备注按当前一级分类内历史使用次数降序排列，最多显示 9 个。
- 点击快捷备注将其填入备注输入框，用户仍可修改。

### 保存行为

新增账单：

- 校验金额、日期、分类；
- 创建或复用二级备注标签；
- 保存账单；
- 更新标签的关联关系；
- 持久化成功后关闭面板并返回明细页；
- 明细、统计、分类详情和标签详情在下次读取时反映最新数据。

编辑账单：

- 可以修改收支类型、一级分类、金额、日期和备注；
- 修改分类时，如果备注非空，必须重新关联新分类下的同名标签，不能继续引用旧分类的标签；
- 清空备注后，账单解除二级标签关联；
- 编辑完成后重新计算相关统计。

删除账单：

- 最终删除前必须有一次明确确认；
- 删除成功后返回明细页；
- 所有统计、分类金额、标签使用次数和金额必须同步反映删除结果；
- 删除账单不自动删除已创建的备注标签。

## 3.4 图表首页

### 顶部切换

- 收入/支出下拉切换；
- 周、月、年三段式切换；
- 当前周期横向选择栏；
- 当前选中周期使用黑色下划线强调。

### 头部固定行为

- 黄色头部区域与其下方周期横条属于同一个固定头部。
- 用户向上或向下滚动图表页内容时，该固定头部必须保持原位，不随内容滚动。
- 固定头部高度在图表页和一级分类详情页之间必须保持一致，不允许点击一级分类后出现头部整体变矮或变高。

### 周期规则

- 周：周一至周日。
- 默认选中最近一个完整周，即”上周”。
- 周视图展示最近 6 个完整周的选择入口。
- 月：默认选中明细页当前选中的月份，展示最近 7 个月的选择入口。
- 年：默认选中明细页当前选中月份所属年份，展示最近 6 年的选择入口。
- 用户切换月份后，月视图和年视图的默认锚点同步更新。
- 周视图以设备当前日期为锚点，不因切换明细页月份而改变。
- 首次进入图表页默认展示支出/上周；用户主动切换图表类型、周期和周期项后，离开页面再返回时保留选择，并通过 DataStore 持久化轻量偏好。

### 概览统计

显示：

- 当前周期总收入或总支出；
- 平均值；
- 当前周期最高单日金额；年视图改为最高单月金额。

平均值口径：

- 周：周期总额 ÷ 7；
- 月：周期总额 ÷ 当月实际天数；
- 年：周期总额 ÷ 12。

金额为 0 时显示 `0.00`。

### 趋势图

- 周：7 个每日数据点。
- 月：当月每日数据点。
- 年：12 个每月数据点。
- 无数据日期仍保留横轴位置，金额为 0。
- 点击数据点只改变选中高亮状态，不改变账单。
- 趋势图按当前收入/支出类型和周期过滤。

### 一级分类排行榜

- 按当前收支类型展示有账单的一级分类。

# 4. 数据模型与业务约束

## 4.1 Category：一级分类

建议字段：

| 字段           | 类型    | 说明                                      |
|:---------------|:--------|:------------------------------------------|
| id             | String  | 稳定分类 ID                               |
| name           | String  | 分类名称                                  |
| normalizedName | String  | 规范化名称，用于同类判重                  |
| type           | Enum    | EXPENSE / INCOME                          |
| iconKey        | String  | 本地图标资源标识                          |
| sortOrder      | Int     | 当前收支类型下的显示顺序                  |
| isSystem       | Boolean | 是否系统预设分类                          |
| isVisible      | Boolean | 是否显示在记账一级分类选择网格            |
| createdAt      | Instant | 创建时间                                  |

系统预设分类必须在首次启动时初始化。系统预设分类分为默认显示分类和可选分类；可选分类初始 `isVisible=false`，通过“更多类别”中的加号启用。自定义分类创建后初始 `isSystem=false`、`isVisible=true`，并追加到当前收支类型的末尾。

V1 默认显示分类与可选系统预设分类如下（用户可在分类管理中调整显示状态和顺序）：

- 支出默认显示：餐饮、购物、日用、交通、运动、娱乐、通讯、服饰、住房、医疗、学习、宠物、礼物。
- 支出可选预设：办公、维修、亲友、快递、礼金、数码、社交、旅行。
- 收入默认显示：工资、兼职、理财、礼金、其他。
- 收入可选预设：奖金。

正式 APP 首次启动不创建任何用户自定义分类；用户通过“＋添加类别”自行创建。HTML 原型为贴合参考图，预置“存款”“其他”两个仅供交互演示的自定义分类样例，不代表正式 APP 的初始数据。

显示顺序由 `sortOrder` 控制，支出与收入分别排序。系统分类和自定义分类均允许隐藏/恢复；隐藏只改变 `isVisible`，不得删除 Category 记录。

分类 ID 必须稳定，不得依赖列表顺序或中文名称生成。自定义分类名称最多 4 个汉字；同一收支类型内名称不可重复，建议使用 `(type, normalizedName)` 唯一约束。自定义分类修改名称或图标时保持 ID 不变。

“设置”固定入口不属于 Category 实体，不写入 Room 分类表，不参与排序和可见性配置。

## 4.2 NoteTag：二级备注标签

建议字段：

| 字段           | 类型    | 说明                 |
|:---------------|:--------|:---------------------|
| id             | Long    | 主键                 |
| categoryId     | String  | 所属一级分类         |
| displayName    | String  | 展示名称             |
| normalizedName | String  | 用于判重的规范化名称 |
| createdAt      | Instant | 首次创建时间         |

唯一约束：

`UNIQUE(categoryId, normalizedName)`

数据库还应建立 `(id, categoryId)` 唯一索引，并在 Transaction 上使用 `(noteTagId, categoryId)` 复合外键引用，尽可能由 SQLite 约束标签与账单的分类归属一致。Category 与 NoteTag 被引用时使用 RESTRICT，V1 不允许删除仍被引用的分类或标签。

说明：

- 二级标签必须归属于一个一级分类。
- 不同分类允许存在同名标签。
- 不同分类的使用次数和消费金额完全独立。
- 标签使用次数、金额和最近使用日期均从 Transaction 计算，不单独保存冗余计数。
- 删除最后一笔关联账单后，标签记录仍保留，可再次快捷选择。
- V1 不提供标签重命名、删除和隐藏管理入口。

## 4.3 Transaction：账单

建议字段：

| 字段         | 类型      | 说明                  |
|:-------------|:----------|:----------------------|
| id           | Long      | 主键                  |
| type         | Enum      | EXPENSE / INCOME      |
| categoryId   | String    | 一级分类 ID           |
| noteTagId    | Long?     | 二级备注标签 ID，可空 |
| noteSnapshot | String?   | 保存时的备注文本快照  |
| amountMinor  | Long      | 金额，单位为分        |
| occurredOn   | LocalDate | 账单发生日期          |
| createdAt    | Instant   | 创建时间              |
| updatedAt    | Instant   | 最后修改时间          |

约束：

- `amountMinor > 0`。
- 金额以分为最小单位。
- `categoryId` 必须存在。
- 分类的收支类型必须与账单 `type` 一致。
- `noteTagId` 非空时，标签必须属于该账单的 `categoryId`。
- 编辑账单时保留原 `createdAt`，只更新 `updatedAt`。
- `occurredOn` 存储为 ISO-8601 日期字符串；`createdAt`、`updatedAt` 使用 UTC Instant，并在界面按设备本地时区展示。
- `noteTagId` 与 `noteSnapshot` 必须同时为空或同时非空。
- `noteSnapshot` 用于保留本笔账单实际展示的备注文本；标签分析、快捷选择和标签详情均按 `noteTagId` 聚合。
- 编辑账单时若备注规范化后命中现有标签，复用该标签 ID；若修改备注，则查找或创建对应标签。

## 4.4 Settings：应用设置

使用 DataStore 保存轻量 UI 偏好，例如最近查看的月份、图表类型和图表周期。V1 币种按固定 CNY 处理，不提供货币切换设置。

不将账单、分类或备注标签放入 DataStore。

## 4.5 核心数据关系

``` text
Category 1 ───── N Transaction
Category 1 ───── N NoteTag
NoteTag  1 ───── N Transaction（可选关联）
```

一笔 Transaction：

- 必须属于一个 Category；
- 最多关联一个 NoteTag；
- 可以没有 NoteTag。

# 5. 关键业务规则

## 5.1 标签归属和快捷排序

快捷标签查询必须使用当前选中的 `categoryId`。

统计范围：

- 统计该分类下全部历史账单；
- 不受当前月份、周/月/年图表筛选影响；
- 仅用于记账页面的快捷标签排序。

排序：

1.  使用次数降序；
2.  最近一笔关联账单日期降序；
3.  标签名称稳定排序。

最多显示 9 个。

## 5.1A 一级分类显示与排序

- 记账页只展示当前收支类型下 `isVisible=true` 的分类，并按 `sortOrder` 升序排列。
- 常驻“设置”入口始终作为分类网格最后一个 UI 项，不写入分类表。
- 分类管理中的减号将 `isVisible` 设为 false；加号将其设为 true 并追加到当前列表末尾。
- 拖动排序只更新当前收支类型内的 `sortOrder`，不改变分类 ID 和账单关联。
- 隐藏分类仍参与历史账单、图表排行榜、分类详情、CSV/JSON 导出与 JSON 恢复。
- 自定义分类改名或换图标时保留分类 ID；历史账单按 ID 自动展示更新后的分类名称和图标。
- 分类设置和自定义分类属于账务数据的一部分，必须纳入 JSON 完整备份与恢复；不放入 DataStore UI 偏好。

## 5.2 编辑账单时的标签迁移

场景：原账单为”餐饮 → 午饭”，用户将一级分类改为”日用”。

处理规则：

1.  原账单解除与”餐饮 → 午饭”的关联；
2.  在”日用”分类下查找同名备注；
3.  如果存在则复用；
4.  如果不存在则创建”日用 → 午饭”；
5.  更新账单的 `categoryId`、`noteTagId` 和 `noteSnapshot`；
6.  整个编辑过程必须在一个数据库事务中完成。

不得将”餐饮 → 午饭”的标签 ID 直接用于日用分类。

## 5.3 统计口径

所有统计必须基于 Transaction 实时查询或由 Room 查询流计算。

禁止：

- 将统计金额作为独立真值保存；
- 手动维护标签使用次数；
- 删除账单后只更新部分统计；
- 将不同一级分类下的同名备注合并。

金额汇总使用整数分计算，展示时转换为两位小数。

## 5.4 日期与时间

- 日期使用设备本地时区解释。
- 账单发生日期与记录创建时间分离。
- 周一为每周第一天。
- 周视图按完整自然周计算。
- 日期筛选使用闭区间。
- 数据库中不使用带时区时间戳直接代替账单日期。

# 6. 数据管理与安全

## 6.1 CSV 导出

“我的”页面中的“导出账单数据”导出全部历史账单；“我的”页面中的“数据备份”单独执行 JSON 完整备份，两者不得共用同一种文件格式。

字段：

- 账单日期；
- 收支类型；
- 金额；
- 一级分类；
- 二级备注；
- 创建时间；
- 最后修改时间。

要求：

- UTF-8 编码，添加 BOM，便于 Excel/WPS 正确识别中文；
- 正确处理逗号、引号和换行；
- 按账单日期倒序导出；
- 不导出内部数据库 ID；
- 不提供 CSV 导入。
- 使用 Android `ACTION_CREATE_DOCUMENT`/Storage Access Framework 让用户选择保存位置。
- 用户取消文件保存时不提示导出成功；只有文件写入完成后才提示成功。

## 6.2 JSON 完整备份

“我的”页面中的“数据备份”入口生成完整 JSON 文件。建议文件名：`ledger-backup-YYYYMMDD-HHmmss.json`。通过 Android `ACTION_CREATE_DOCUMENT`/Storage Access Framework 让用户选择保存位置。

备份至少包含：

- `schemaVersion`；
- `appVersion`；
- `exportedAt`；
- categories（系统分类、自定义分类、图标、显示状态和排序）；
- noteTags；
- transactions。

JSON 备份保留主键及关联 ID，确保恢复后账单、分类和备注标签关系不变；同时保留分类显示/隐藏状态与支出、收入各自的排序。DataStore 中的页面偏好不属于账务数据，不纳入备份与恢复。恢复时必须先确认所有引用 ID 均存在，且标签与账单所属分类一致。

备份必须包含用户自定义分类、备注标签和全部账单。

## 6.3 JSON 恢复

恢复规则：

1.  使用 Android Storage Access Framework 选择 JSON 文件；
2.  检查文件格式、schemaVersion 和兼容性；
3.  在写入数据库前完整解析并校验所有字段；
4.  校验主键唯一性、金额、日期、分类类型、标签归属和关联完整性；
5.  显示将恢复的数据数量，并明确提示会覆盖当前全部账务数据；
6.  用户二次确认后，通过单个 Room `withTransaction` 事务清空旧数据并写入备份；
7.  事务成功后刷新所有页面；
8.  任一步数据库写入失败或协程取消时，事务自动回滚，原数据保持不变。

V1 JSON 恢复模式为**完整替换**，不是合并导入。恢复前必须明确提示将覆盖当前全部账单、分类和备注标签，并要求用户二次确认。该行为已由用户明确确认。

旧版本备份若不兼容，必须明确提示，不得静默丢弃字段或部分导入。JSON 恢复使用 `ACTION_OPEN_DOCUMENT`/Storage Access Framework，不申请全盘文件访问权限。

## 6.4 本地隐私

- 账单数据保存在 APP 私有目录。
- Android Manifest 不声明 `INTERNET` 权限。
- `android:allowBackup` 显式设为 `false`；同时检查最终合并后的 Android Manifest，确保没有依赖间接引入 `INTERNET` 权限。
- Android 12+ 配置 `dataExtractionRules`，排除 cloud-backup 和 device-transfer；Android 11 及以下通过 `fullBackupContent` 排除应用数据。
- 不接入广告 SDK、统计 SDK、崩溃上报第三方服务或模型 API。
- 手动 CSV/JSON 文件导出与恢复通过 Storage Access Framework 完成，不申请宽泛存储权限。
- 不实现账号和远程数据传输。
- JSON 备份文件为普通可读取文件，界面应提示用户妥善保管；V1 不提供备份文件加密。

说明：Android Auto Backup 默认可能将应用私有目录和数据库纳入系统备份；仅不声明 `INTERNET` 权限并不能代表已关闭系统备份。Android 12+ 的 `allowBackup=false` 在部分设备上仍不一定阻止设备到设备传输，因此同时配置 `dataExtractionRules` 明确排除 cloud-backup 和 device-transfer。官方文档：[Auto Backup](https://developer.android.com/identity/data/autobackup)。
